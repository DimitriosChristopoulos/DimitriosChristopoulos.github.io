The first step of implementing proper alignment was to use a simple linear algorithm that 'maps' a point in either the G or R channel to a corresponding one in the B channel, and using some sort of loss function to determine the difference in the intensity values between the 2 pixels. Using simple for loops, we can iterate from a lower bound to an upper bound for both the x and y dimensions. Shown below is a simple equation for mapping from a G or R channel to B given a x_offset and y_offset.

G[y,x]→B[y+yoffset,x+xoffset]

Linear Alignment with L2: Provided Images

Right now we have 2 main options for loss functions. The first one used here is L2 normalization, with the equation for it shown below.

L2(I1,I2)=∑y1,x1(I1[y1,x1]−I2[y2,x2])2

Here I1 and I2 are the two image windows being compared, (x1, y1) and (x2, y2) are corresponding pixel positions in the two windows, and the sum runs over every pixel in the window. Lower is better.

Shown below are the overlapping images made by optimizing for the loss function between the G->B channels, and the R->B channels. The final resulting image is of shape [height, width, 3], as now our image has 3 color channels.

Linear Alignment with NCC: Provided Images

The second loss function is normalized cross-correlation (NCC). Instead of measuring the difference between the two windows, it measures how similar they are: each window is divided by its own norm, and the dot product of the two normalized windows is taken, as shown below.

NCC(I1,I2)=∑y,x(I1[y,x]‖I1‖)(I2[y,x]‖I2‖)

Here ‖I‖ is the square root of the sum of the squared pixel values in a window.

Because NCC is a similarity score rather than an error, the best offset is the one that maximizes it, and a value closer to 1 means a better match. Dividing by the norms also makes the score insensitive to overall scale differences between the color channels, which helps because the three plates were exposed through different filters. Shown below are the overlapping images made by optimizing NCC between the G->B channels and the R->B channels. The loss values listed under each image are the best NCC scores found.

Image Pyramid Implementation with L2: Provided Images

The next step is to increase the complexity of our mapping process. We want to blur, and then downsample the image so that we can more freely explore the domain, which right now for bigger JPEG images is very computationally expensive. The solution to this is to downsample the image, so that with the same x and y offset values, we can reach exponentially further throughout the image. First, we blur the image, and then downsample, taking every other point. If the smaller of the 2 dimensions is not less than 200, we keep downsampling the image. Since we keep doing the same thing over and over again, we are able to make this a recursive call.

Once we have downsampled enough to where one of the dimensions of the image has gotten to 200 pixels or less, we can start exploring the offset. We optimize the loss function as much as we can just like before, and pass these optimal offsets to the next call in the stack. For the next call in the stack, this optimal solution is the starting point. This allows for big leaps in offset values in coarser images (the ones downsampled the most), and fine-tuning adjustments as the image is upsampled back up.

Once again there is a choice between L2 and NCC, both are shown below here but they largely provide the same solution, or at least are sufficiently similar.

Border Detection with Canny Edges

The plates have black, white and grey borders, plus thin divider strips between the three exposures. These do not line up between channels, so they show up as colored fringes and can throw off the alignment metric. To find where the real image starts, each channel is lightly blurred and run through Canny edge detection, which marks strong intensity changes as edge pixels.

A border is a long, nearly straight line, so instead of tracing lines we count, for every column and every row, the fraction of pixels marked as edges. Borders span almost the whole height or width, so they score far higher than scene edges like a horizon. The edges are dilated along one direction so slightly ragged borders still stack into a single row or column. We only search a band near each side, keep the rows and columns above a threshold, and take the innermost one on each side as the start of the actual image. The function returns the crop bounds, and the detected lines are drawn over the image so they can be checked by eye.

Contrast Stretching

After alignment the image often uses only part of the available brightness range, so it looks flat. Contrast stretching rescales the intensities so that a dark value maps to 0 and a bright value maps to 1. We use the 1st and 99th percentiles instead of the true minimum and maximum so a few specks or dead pixels cannot set the range, and one shared range for all three channels so the color balance is not changed.

out=clip(x−plophi−plo,0,1)

Here x is a pixel value, and plo and phi are the 1st and 99th percentiles of all pixel values across the three channels.

White Balance

The plates were not exposed under a neutral light, so the combined image can have an overall color tint. We use the gray world assumption: averaged over a whole scene, colors should come out neutral gray, so any leftover tint is treated as the illuminant and divided out. Each channel is multiplied by a gain that moves its mean to the average of all three channel means. Near-black and near-white pixels are left out of the means because they carry little color information.

mavg=mB+mG+mR3 gainc=mavgmc outc=clip(gainc⋅inc,0,1)

Here mc is the mean of channel c (B, G or R) over the pixels that are neither near-black nor near-white.

Saturation Boosting

The three plates are exposures through different color filters, so the differences between channels in the stacked image can be small, and colors can look muted. Saturation boosting pushes each pixel away from its own gray value (the mean of its three channels) by a factor s, which amplifies those color differences. Neutral pixels do not change. We use s = 1.5 for every image. This cannot fix a wrong hue, it only strengthens the color that is already there, and a very large s amplifies noise and edge fringes.

gray=inB+inG+inR3 outc=gray+s(inc−gray)

An s of 1 leaves the image unchanged, and values above 1 increase the saturation.

Cropping the Edge Artifacts

Shifting the G and R channels to line up with B leaves strips along the edges where a channel has no data, and near the plate frame the three exposures disagree, which produces bands of odd colors. To remove them, each side is cropped by the largest shift in that direction, plus a small extra margin, a fraction of the image size, that also removes the colored fringes from the plate frame.

y0=max(0,ΔyG,ΔyR)+py y1=H+min(0,ΔyG,ΔyR)−py x0=max(0,ΔxG,ΔxR)+px x1=W+min(0,ΔxG,ΔxR)−px

Here (ΔyG, ΔxG) and (ΔyR, ΔxR) are the offsets found for the G and R channels, H and W are the image height and width, and the extra margins are py = ⌊fH⌋ and px = ⌊fW⌋ with f = 0.05. The final image is the region from row y0 to y1 and column x0 to x1.
